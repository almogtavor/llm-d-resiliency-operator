Architecture

IRO keeps a multi-node inference engine serving through faults. It watches one engine group, the Pods that run the engine's members (for vLLM, its DP ranks). When a member fails, IRO removes it in place so the rest keep serving, then brings the group back to full capacity by resetting the failed Pod. Only when that cannot work does it restart the whole group.

The controller knows no engine and no workload type. It talks to them through two plugins: the workload (LeaderWorkerSet today) and the engine (vLLM today). Its state lives in a versioned journal, so a new leader picks up a recovery where the old one stopped.

Every failure IRO handles, step by step with every call it makes, is in Failures.

The controller is always in one of three phases. A fault moves it from serving to recovering; a reconfig that removes the dead member brings it back. A ResetAll is the only way back to starting.
